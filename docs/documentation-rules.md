# 문서 작성 규칙

문서를 어디에 어떤 형식으로 두는지에 대한 규칙. 문장·마크다운 규칙은
[writing-rules.md](writing-rules.md)를 따른다.

## 문서의 위치

| 문서 종류 | 위치 |
| --- | --- |
| 수강생이 보는 콘텐츠 (강의·슬라이드·개념·글·소개) | `site/src/content/` — 사이트로 빌드된다 |
| 저장소 운영·개발 규칙 (이 문서 같은 것) | `docs/` |
| 회차별 강의 문서·실습 가이드 | `docs/` (추가 예정) |
| 사이트 개발 안내 (명령·콘텐츠 작성 위치) | `site/README.md` |
| AI 도구용 가이드 | 루트 `CLAUDE.md` — 요약과 링크만 두고, 실제 규칙은 `docs/`에 둔다 |

- 같은 내용을 두 곳에 쓰지 않는다. 상세는 한 곳에만 두고 나머지는 링크한다.
- 새 규칙 문서를 만들면 [docs/README.md](README.md) 목록에 추가한다.
- 저장소 구조가 바뀌면 루트 `README.md`의 "저장소 구조" 트리를 갱신한다.

## 파일·형식 규칙

- **파일명** — 영어 kebab-case: `writing-rules.md`, `git-workflow.md`
- **언어** — 본문은 한국어. 코드·명령·브랜치명·식별자는 원문 그대로 쓴다.
- **구조** — 문서당 h1(`#`) 하나, 바로 아래에 문서의 목적 한두 문장, 이후
  h2(`##`) 섹션으로 나눈다.
- **링크** — 저장소 내부 문서는 상대 경로로 링크한다.
- **날짜** — "최근", "지난주" 같은 상대 표현 대신 절대 날짜(2026-07-24)를 쓴다.
