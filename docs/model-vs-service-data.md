# 모델 대 서비스 데모 데이터

5주차 3장의 `<ModelVsService />`가 쓰는 `site/src/data/model-vs-service.json`을
어떻게 만들었는지의 재현 기록.

지어낸 응답이 없다. 질문 5개를 각각 **두 방식으로 실제 호출**하고, 모델이
돌려준 문장과 `tool_calls`를 그대로 받아 적었다. 도구 구현만 목데이터다.
실제 기상청이나 시계를 부르지 않는다. 이 데모가 보이려는 것은 도구가 돌려준
값이 아니라 구조이기 때문이다.

## 만드는 법

```sh
# week05-agent-lab 저장소에서 (키 필요 — 모델을 실제로 부른다)
docker compose up -d
docker compose exec -T lab python - < …/scripts/extract-model-vs-service.py > mvs.json
```

산출물을 `site/src/data/model-vs-service.json`으로 옮긴다. 호출은 질문당
최대 3회(도구 없이 1회, 도구 왕복 2회)이고 5문항이라 한 번 뽑는 데 몇 센트도
들지 않는다.

## 스크립트가 하는 일

`scripts/extract-model-vs-service.py`

- 질문 하나를 **① 도구 없이** 한 번, **② `tools`를 실어** 한 번 보낸다
- ②에서 모델이 도구를 요청하면 목데이터 함수를 실행해 `role: tool` 메시지로
  되돌려주고, 최종 답까지 받는다. 요청한 도구 이름·인자·실행 결과를 그대로 남긴다
- 산수 질문은 정답을 파이썬으로 계산해 두 답을 각각 채점한다(`correct`)
- 질문마다 `hole`(지식·정확성·행동·없음)을 붙여, 도구 없이 답이 안 나오는
  이유의 종류를 표시한다

도구 4종은 전부 결정적이다. 날씨는 고정값, 시각은 고정 타임스탬프, 계산기는
사칙연산만 허용하는 `eval`, 파일 목록은 고정 배열이다. 다시 뽑아도 도구 쪽
값은 같고 모델의 문장만 달라진다.

## 실측하며 나온 것

- **산수에서 모델이 자신 있게 틀렸다.** `3847 × 29183`의 정답은
  112,267,001인데 도구 없는 답은 **112,267,021**이었다. 스무 개 차이라
  눈으로는 그럴듯하고, 모델은 망설이는 기색 없이 숫자만 내놓았다. 도구를
  쥐여주자 계산기가 정확한 값을 냈다. "모델의 산수는 계산이 아니라 그럴듯한
  확률"이라는 문장의 실물이다
- **모델은 모르는 것을 대체로 안다.** 날씨·시각·파일 목록 질문에서는
  "실시간 정보에 접근할 수 없다"고 스스로 밝혔다. 위험한 쪽은 이렇게 거절하는
  질문이 아니라, 거절 없이 틀린 값을 내놓는 산수 쪽이다
- **필요 없으면 부르지 않는다.** 여행 추천 질문에서는 도구 4개를 쥐여줬는데도
  `tool_calls`가 비어 있었다. 도구를 붙였다고 매번 부르는 것이 아니라는 것을
  같은 화면에서 보이려고 이 문항을 넣었다

## 다시 뽑을 때

- 모델의 문장은 실행마다 달라진다. 특히 **산수 질문이 우연히 맞을 수 있다.**
  그러면 교안 본문("자신 있게 틀렸다")과 어긋나므로, 본문을 실제 결과에 맞춰
  고치거나 그 실행을 다시 뜬다. 데이터에 맞춰 문장을 고치지, 문장에 맞춰
  데이터를 고르지 않는다
- `correct` 판정은 쉼표를 지운 문자열 포함 검사다. 모델이 "약 1억 1226만"처럼
  풀어 쓰면 오답으로 잡힌다. 그럴 때는 판정 로직이 아니라 프롬프트("숫자만
  답해줘")를 먼저 확인한다
