# 콘텐츠 작성 규칙

`site/` 아래 모든 콘텐츠(강의·글·개념·슬라이드·페이지)와 저장소 문서(README 등)에
적용하는 기본 규칙. 사람이 쓰든 AI가 쓰든 동일하게 따른다.

## 한글 문장 스타일

- **닫는 괄호로 끝나는 문장에는 마침표를 겹치지 않는다.** `).` 형태를 만들지 않는다.
  - 좋음: `커리큘럼 표에서 산출물 열 제거 (회차·주제 2열로)`
  - 나쁨: `커리큘럼 표에서 산출물 열 제거 (회차·주제 2열로).`

## 마크다운 규칙

- **소프트 줄바꿈(하드 브레이크)** — 같은 문단 안에서 줄을 바꾸고 싶으면
  줄 끝에 **스페이스 2개**를 붙이고 엔터. 스페이스 없이 엔터만 치면 렌더링될 때
  앞 줄에 그대로 이어진다. 빈 줄 하나는 문단 분리다.
- **표 안의 파이프는 이스케이프** — `|`는 표의 셀 구분자이므로, 셀 내용에
  파이프가 들어가면 `\|`로 쓴다. 위키링크도 마찬가지:
  - 표 안: `[[llm\|LLM]] API와 프롬프트`
  - 표 밖: `[[llm|LLM]]` 그대로 사용 가능
- **물결표(~) 주의** — 한 문단에 `~`가 두 개 있으면 그 사이가 취소선으로
  렌더링된다. 회차·범위 표기는 `1\~9회차`, `10\~14회차`처럼 이스케이프한다.
  코드 블록과 mermaid 블록 안에서는 이스케이프하지 않는다.
- **볼드 경계와 문장부호+한글** — 닫는 `**` 바로 앞이 닫는 괄호·따옴표 같은
  문장부호이고 바로 뒤에 한글(조사 등)이 붙으면, CommonMark 규칙상 강조로
  인식되지 않아 `**`가 화면에 그대로 노출된다.
  - 나쁨: `**요구사항 설계(지시)와 검증(판단)**이고` — `)**이` 지점에서 깨짐
  - 해결 1 (권장): 볼드 뒤에 조사가 바로 붙지 않게 문장을 다듬는다 —
    `**요구사항 설계(지시)와 검증(판단)** 두 가지이고`
  - 해결 2: 괄호를 볼드 밖으로 뺀다 — `**요구사항 설계**(지시)`
  - 해결 3: 문장을 못 바꾸면 `<strong>…(판단)</strong>이고`처럼 HTML 태그를 쓴다
  - 참고: `**볼드**(괄호)`처럼 볼드가 한글·영문으로 끝나고 뒤에 괄호가 오는
    형태는 문제없다. 문제는 볼드 경계가 "문장부호와 한글 사이"에 끼는 경우다
- **위키링크는 등록된 용어만** — `[[용어]]`는 `site/src/data/glossary.mjs`에
  등록된 키만 쓸 수 있다. 미등록 용어는 빌드가 실패하는데, 이는 의도된
  동작이다. 새 용어는 먼저 glossary.mjs에 추가한 뒤 본문에서 참조한다.

## 슬라이드 규칙

- **줄바꿈 위치를 눈으로 확인한다.** 테마가 한글을 어절 단위로만 줄바꿈하도록
  처리하므로(word-break: keep-all) 글자 단위로 깨지지는 않지만, 마지막 어절
  하나만 다음 줄로 넘어가는 등 어색한 자리에서 꺾일 수 있다. 덱을 작성·수정한
  뒤에는 반드시 브라우저에서 슬라이드를 넘겨보며 제목·부제·리스트의 줄바꿈을
  확인한다.
- **어색하면 끊는 위치를 직접 정한다.** 하드 브레이크(스페이스 2개 + 엔터)로
  의도한 자리에서 줄을 나누거나, 문구 자체를 짧게 다듬는다.
- 화면 크기에 따라 줄바꿈이 달라지므로, 창 폭을 좁혀가며 한 번 더 확인하면
  좋다.

## 커밋 전 검증

- 사이트 콘텐츠를 고쳤으면 `cd site && pnpm build && pnpm check`가 통과해야
  한다. 표가 깨졌는지, 취소선이 생겼는지는 빌드만으로 잡히지 않으므로
  해당 페이지를 열어 눈으로 확인한다.
