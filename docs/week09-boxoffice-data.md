# week09 박스오피스 데이터 실측 기록

9주차 교안 2장 6절의 수치가 나온 자리. 추정하지 않고 **1년치를 실제로 받아
전수조사한 것**이다. 4주차 가공식품 DB와 같은 방식이고, 다른 점은 이번 데이터가
회차의 주인공이 아니라 무대라는 것뿐이다.

## 무엇을 어디서

| | |
| --- | --- |
| 출처 | 영화진흥위원회 영화관입장권통합전산망(KOBIS) 일별 박스오피스 |
| 주소 | `https://www.kobis.or.kr/kobis/business/stat/boxs/findDailyBoxOfficeList.do` |
| 기간 | 2025-09-01 \~ 2026-08-31 (365일) |
| 수집일 | 2026-09-17 |
| 방식 | 통계 페이지에 POST. `robots.txt`는 `allow: /` |

**API 키가 필요 없다.** KOBIS 오픈API는 키 발급이 필요하지만, 통계 화면은
공개이고 한 번의 요청으로 최대 7일치를 돌려준다. 수강생이 계정을 만들지 않아도
재현되게 하려고 이쪽을 택했다.

요청에 두 가지가 걸린다.

- **CSRF 토큰**: 페이지를 먼저 GET해서 `name="CSRFToken"`의 값을 꺼내 함께 보낸다
- **기간 상한**: `sSearchFrom`\~`sSearchTo`가 7일을 넘으면 조회 에러 페이지가
  온다. 한 달을 한 번에 요청하면 4.7KB짜리 에러 문서가 돌아온다

그래서 주 단위로 끊어 53회 요청한다. 0.8초 간격으로 약 2분 걸린다.

## 응답을 읽을 때의 함정

하루치가 표 **두 개**로 온다. 1\~10위가 한 표, 11위 이하가 다른 표다. 그리고
7일을 요청하면 **표가 날짜별로 묶이지 않고 종류별로 묶여서** 온다.

```plaintext
table 0..6    각 날짜의 1~10위   (최신 날짜부터 역순)
table 7..13   각 날짜의 11위 이하 (최신 날짜부터 역순)
```

표 순서로 날짜를 계산하면 어긋난다. 실제로 처음에 그렇게 짰다가 9월 데이터가
11월 자리에 들어갔다. **각 `<table>` 바로 앞의 캡션에서 날짜를 읽는다.**

```plaintext
… 더보기 2026년 01월 07일(일)  <table>
```

영화 코드는 셀에 없고 링크의 `onclick`에 있다.

```html
<a href="#" onclick="mstView('movie','20203702');return false;" title="노량: 죽음의 바다">
```

## 영화 마스터

일별 실적에는 영화 코드와 제목·개봉일만 있다. 장르·등급·국가·배급사·시놉시스는
상세 페이지에서 가져온다.

```plaintext
https://www.kobis.or.kr/kobis/business/mast/mvie/searchMovieDtl.do?code={movieCd}&sType=
```

표본 60편으로 잰 결과다.

| | 값 |
| --- | --- |
| 성공 | 60 / 60 |
| 편당 소요 | 0.85초 (0.35초 슬립 포함) |
| 5,452편 전량 추정 | 약 77분 |
| **750편(컷 적용) 추정** | **약 11분** |

필드 채움률.

| 필드 | 채움 |
| --- | --- |
| 장르 · 등급 · 국가 · 상영시간 · 영화구분 | 60 / 60 |
| 시놉시스 | 55 / 60 |
| 배급사 | 36 / 60 |
| 제작사 | 11 / 60 |

**파싱은 위치가 아니라 생김새를 기준으로 해야 한다.** 요약정보 블록의 앞 세
칸(형태·영화구분·장르)은 늘 있지만 뒤의 셋(러닝타임·등급·국가)은 빠질 수
있다. 인덱스로만 자르면 등급이 없는 영화에서 한 칸씩 밀려 국가 자리에
`등급분류`라는 **섹션 제목**이 들어앉는다.

고치고 나서 한 번 더 걸렸다. 등급을 지금 쓰는 다섯 가지 집합으로 잡았더니
**옛 영화가 옛 등급 이름을 달고 왔다.**

```plaintext
15세관람가 8 · 12세관람가 5 · 18세관람가 4
12세 미만인 자는 관람할 수 없는 등급 3 · 연소자관람가 2 · 고등학생이상관람가 2
```

750편 중 28편이 그랬다. 재개봉 클래식이 많은 데이터라 등급 어휘가 여러 세대
섞여 있다. 집합이 아니라 무늬(`관람가|관람불가|관람할 수 없는`)로 잡는다.

## 심어 둔 함정

랩에는 원본에 없는 행이 하나 있다. `movie_cd`가 `90000001`이고, 시놉시스에
프롬프트 인젝션 한 줄이 들어 있다. 교안 9장 2절의 실습용이다.

4주차는 실데이터의 오염을 찾아냈고, 9주차는 방어가 도는 것을 보이려고 함정을
놓았다. **심었다는 사실을 교안에도 적는다.** 숨기면 실측이 아니라 연출이다.

## 다시 뜰 때 유의할 점

- 기간을 바꾸면 교안의 모든 수치가 달라진다. 기본값을 바꾸려면 교안 2장 6절과
  이 문서를 함께 고친다
- KOBIS가 화면 구조를 바꾸면 파서가 깨진다. 캡션에서 날짜를 읽는 부분과
  `mstView` 정규식이 먼저 깨질 자리다
- 최근 일자는 보정이 들어간다. 상영 마감과 정정 때문에 며칠간 값이 움직이므로,
  수집일 직전 며칠은 나중에 다시 받으면 숫자가 달라질 수 있다
- 요청 간격을 0.8초 아래로 줄이지 않는다. 공개 통계 화면이고 막을 이유를
  만들 필요가 없다

## 누적 관객의 함정

`audi_acc`(누적 관객)로 "1년 동안 가장 많이 본 영화"를 뽑으면 이렇게 나온다.

```plaintext
왕과 사는 남자     16,921,397   개봉 2026-02-04
국제시장          14,269,712   개봉 2014-12-17   ← 재개봉
아바타: 물의 길     10,824,614   개봉 2022-12-14   ← 재개봉
보헤미안 랩소디      9,962,228   개봉 2018-10-31   ← 재개봉
```

**재개봉작은 원래 흥행분을 이고 온다.** 집계는 맞는데 문장이 틀리는 자리이고,
숫자만 대조하는 검증으로는 잡히지 않는다. 지표 사전의 `audi_acc` 항목에
"합산하지 않고 최댓값을 쓴다"를 적어 둔 이유다. 교안 8장 1절에서 이 장면을
쓴다.
